# План рефакторинга и улучшения — 3D Tetris

> Документ для передачи локальному агенту Claude Code.
> Каждая задача самодостаточна: содержит контекст, файлы с номерами строк, шаги
> и критерии приёмки. Выполнять можно по фазам сверху вниз; внутри фазы — по
> порядку. После каждой задачи: собрать, прогнать тесты, закоммитить.

## Контекст проекта

3D-тетрис в стиле Blockout, C++20 + OpenGL 3.3 (GLFW + GLAD + Dear ImGui).
Зависимости тянутся через CMake FetchContent (на первом клоне нужен интернет;
в репо стоит `FETCHCONTENT_FULLY_DISCONNECTED=TRUE`, см. `CMakeLists.txt:10`).

Размеры на момент составления плана (~4100 строк):

| Файл | Строк | Роль |
|---|---|---|
| `src/app.cpp` | 1517 | main loop, рендер, ввод, ImGui — **монолит**, `main()` со строки 327 до конца |
| `src/game.cpp/.h` | 755 | ядро: Well, Piece, физика, вращения, очистка плоскостей |
| `src/game_ai.cpp/.h` | 407 | AI-планировщик: перебор 24 ориентаций × позиций + BFS достижимости |
| `src/config.cpp/.h` | 465 | загрузчик TOML, определения форм |
| `src/render.cpp/.h` | 207 | GLSL-шейдеры, палитра |
| `src/geometry.h` | 241 | построение мешей (кубы, рёбра, пол, стены) |
| `src/math.h` | 184 | линал (Vec3, Vec3i, Mat4, perspective, look_at) |
| `src/shader.h` | 34 | компиляция/линковка GLSL |

### Сборка и запуск
```bash
cmake -B cmake-build-debug -DCMAKE_BUILD_TYPE=Debug
cmake --build cmake-build-debug
./cmake-build-debug/3dtetris
```
> ВНИМАНИЕ: при правках в каждой фазе обязательно проверять, что проект всё ещё
> собирается. Запуск требует GPU/дисплея — на CI/headless проверяй сборку, а не
> рантайм. Игровое ядро должно собираться и тестироваться без OpenGL.

# ФАЗА 1 — Тестируемость и CI (высокий приоритет)

> Это фундамент: тесты ловят регрессии до того, как мы начнём двигать код в Фазе 2.

## 1.1 Сделать игровое ядро собираемым без OpenGL
**Проблема:** логика (`game.*`, `game_ai.*`, `config.*`, `math.h`, `geometry.h`)
не зависит от GL, но CMake собирает всё одной целью с GLFW/GLAD/ImGui.
**Шаги:**
- В `CMakeLists.txt` выделить статическую библиотеку `tetris_core` из файлов,
  не требующих GL: `game.cpp`, `game_ai.cpp`, `config.cpp` (+ заголовки
  `math.h`, `geometry.h`, `game.h`, `game_ai.h`, `config.h`).
- Исполняемый `3dtetris` линкуется с `tetris_core` + GL-слой (`app.cpp`,
  `render.cpp`, `shader.h`).
- Проверить, что `geometry.h` действительно не тянет GL-типы; если тянет —
  разделить чисто-геометрическую часть (генерация вершин в `std::vector<float>`)
  от загрузки в GL-буферы (которая остаётся в `app.cpp`).
**Приёмка:** `tetris_core` собирается отдельной целью без линковки с GLFW/GLAD.

## 1.2 Подключить тест-фреймворк
**Шаги:** добавить GoogleTest или Catch2 через FetchContent (Catch2 — header-only,
проще для оффлайн). Создать каталог `tests/` и цель `ctest`.
**Приёмка:** `ctest` запускает пустой smoke-тест и проходит.

## 1.3 Юнит-тесты игрового ядра
**Покрыть в первую очередь (всё детерминировано, без рантайма GL):**
- **Вращения:** из тождественной матрицы перебором осей получить ровно
  **24 уникальные ориентации** (группа вращений куба). Проверить, что
  `apply_rot` (`game.h:46`) + последовательные `mul_rot` (`game.cpp:58`) не
  выходят за пределы 24 и каждая матрица ортогональна с det=+1.
- **Очистка плоскостей:** `clear_full_planes` / `clear_full_planes_range`
  (`game.cpp:333/338`) — заполнить плоскость, проверить, что она исчезает и
  верхние оседают; частично заполненная — остаётся.
- **Границы стакана:** `Well::in_bounds` / `is_free` (`game.cpp:119/126`).
- **Top-out / GameOver:** заспавнить в занятую зону — состояние `GameOver`.
- **7-bag:** `draw_from_bag` (`game.cpp:226`) — за один «мешок» каждая форма
  ровно один раз; зафиксировать seed RNG для детерминизма.
- **Фиксация фигуры:** `Well::lock_piece` (`game.cpp:143`) кладёт правильные клетки.
**Приёмка:** ≥ 6 групп тестов зелёные; покрытие ключевых инвариантов ядра.

## 1.4 Тесты AI-планировщика
**Файлы:** `src/game_ai.cpp`.
**Шаги:** на маленьком стакане проверить, что план достижим (последовательность
шагов реально приводит фигуру в целевую позицию через публичный API игры) и что
эвристика предпочитает очистку плоскости падению с дырами.
**Приёмка:** план из AI, применённый к копии игры, воспроизводит предсказанное
итоговое поле без рассинхрона.

## 1.5 GitHub Actions CI
**Шаги:** `.github/workflows/ci.yml`:
- job `build-and-test`: ubuntu, установить GL/X11 dev-пакеты для GLFW
  (`libgl1-mesa-dev xorg-dev`), сконфигурировать CMake, собрать, `ctest`.

# ФАЗА 2 — Устранение дублирования и развязка

## 2.1 Единый источник матриц вращения (важно)

README прямо признаёт, что они держатся «вручную синхронно» — это хрупко и
создаёт риск plan/execution-рассинхрона в AI.
**Шаги:**
- Создать `src/rotation.h` (header-only): константы `ROT_X_POS/NEG`,
  `ROT_Y_POS/NEG`, `ROT_Z_POS/NEG`, функции `mul_rot`, `apply_rot`
  (последняя сейчас в `game.h:46`).
- Заменить локальные определения в `game.cpp` и `game_ai.cpp` на `#include "rotation.h"`.
- Вывести NEG-матрицы либо как константы, либо как транспонирование POS (для
  ортогональных целочисленных матриц обратная = транспонированная) — но не менять
  численные значения относительно текущих, чтобы поведение совпало 1:1.
**Приёмка:** ровно одно определение каждой матрицы и `mul_rot` в кодовой базе;

## 2.2 Разбить app.cpp на модули
**Проблема:** `app.cpp` 1517 строк, `main()` со строки 327 — один цикл с
рендером, вводом и ImGui-вёрсткой вперемешку (несколько `ImGui::Begin`:

**Целевая декомпозиция (без смены поведения):**
- `src/gfx/mesh.{h,cpp}` — `GlMesh`, `make_mesh`, `update_mesh`, `destroy_mesh`,
  `append_face` (сейчас `app.cpp:29-280`).
- `src/gfx/renderer.{h,cpp}` — настройка пайплайна, отрисовка стакана/фигур/
  пола/рёбер, свет (Phong, 3 орбитальных источника).
- `src/input.{h,cpp}` — GLFW-колбэки (`framebuffer_size_callback:283`,

- `src/ui/hud.{h,cpp}` — ImGui-панели (Viewport/Iso/Controls/HUD/overlays).
- `src/app.cpp` — тонкий: инициализация (`init_glfw:296`, `init_glad:316`),

**Стратегия:** двигать по одному блоку за коммит, после каждого — сборка зелёная.
Сначала чистые куски (mesh), затем ввод, затем UI, в конце — ужать `main()`.
**Приёмка:** ни один файл в `src/` не длиннее ~400 строк; поведение игры и
